Simplifying LLM Interaction

Directly calling an LLM API involves complex boilerplate for authentication and token management. Our `Tachyon-Langchain Client` wrapper abstracts this away, making the process clean and simple.

The Hard Way: Direct API Call

When making direct calls to an LLM API hosted on Apigee, you face several challenges. You need to manually handle token generation, ensure tokens are renewed before expiration, and manage error conditions like unauthorized access. This adds significant complexity to every LLM interaction.

# Lots of boilerplate required for token management and error handling!
import requests, json, time

# Global variables to store token and its expiry time
access_token = None
token_expiry = 0 

def get_new_token():
    # Imagine complex logic here for OAuth2 client credentials flow
    # This would involve a separate HTTP POST request to an authentication server
    print("Fetching new access token...")
    # Simulate token generation and expiry
    return "simulated_new_access_token", time.time() + 3600 # Token valid for 1 hour

def get_valid_token():
    global access_token, token_expiry
    # Check if token is missing or expired (with a buffer for renewal)
    if access_token is None or time.time() >= token_expiry - 60: # Renew 60s before expiry
        access_token, token_expiry = get_new_token()
    return access_token

def call_llm_direct(messages):
    token = get_valid_token()
    if not token:
        return {"error": "Failed to obtain valid token."}

    headers = {
        "Authorization": f"Bearer {token}",
        "Content-Type": "application/json"
    }
    payload = {"model": "gpt-4o", "messages": messages}
    
    try:
        response = requests.post("https://your-apigee-domain.com/openai/v1/chat/completions", headers=headers, json=payload)
        response.raise_for_status() # Raises HTTPError for bad responses (4xx or 5xx)
        return response.json()
    except requests.exceptions.HTTPError as e:
        # Handle specific HTTP errors, e.g., 401 Unauthorized for token issues
        if e.response.status_code == 401:
            print("Token unauthorized, forcing re-authentication.")
            global access_token, token_expiry
            access_token = None # Invalidate token to force renewal on next call
        return {"error": f"API Error: {e.response.status_code} - {e.response.text}"}
    except Exception as e:
        return {"error": f"An unexpected error occurred: {e}"}

MCP: The Standard for Tools

While simple Python functions are a good start for defining tools, they quickly hit limitations in a complex, enterprise-grade agentic ecosystem. The Model Context Protocol (MCP) provides a robust standard for creating tools that are discoverable, reusable, and independently deployable. We leverage `FastMCP` to make this process efficient and automated.

Problem: Simple Python Functions

  • ❌Not Reusable: Copying and pasting function code across different agents or projects leads to significant code duplication and makes maintenance a nightmare.
  • ❌Not Discoverable: Without a central registry or standardized interface, agents (or developers) have no easy way to discover what tools are available or how to use them.
  • ❌No Standard: Different teams might implement similar functionalities in inconsistent ways, hindering interoperability and making it difficult to integrate tools from various sources.
  • ❌Tightly Coupled: Simple Python functions are typically embedded directly within an agent's codebase. This tight coupling means that tools cannot be deployed, scaled, or updated independently of the agents that use them.
  • ❌Complex API Integration: If a tool needs to call an external API, the Python function itself must handle API keys, rate limits, error handling, and request/response parsing, adding significant complexity to each tool.

Solution: MCP Tools with `FastMCP`

MCP defines a machine-readable protocol for describing tool capabilities, similar to OpenAPI for web services. `FastMCP` automates the creation of these MCP-compliant tools.

  • ✅Reusable: Define a tool once with MCP, and it can be invoked by any agent or application that understands the MCP standard, typically via a simple HTTP API call.
  • ✅Discoverable: `FastMCP` automatically generates a standardized MCP definition (like an OpenAPI spec) for each tool, which can be registered in a central catalog. Agents can then dynamically discover and understand these tools.
  • ✅Standardized: The `@mcp.tools()` decorator enforces a consistent structure for tool definitions (inputs, outputs, descriptions), ensuring uniformity across all tools in the ecosystem.
  • ✅Decoupled & Scalable: MCP tools are exposed as independent microservices (e.g., FastAPI endpoints managed by `FastMCP`). This allows them to be developed, deployed, and scaled independently of the agents, improving system resilience and scalability.
  • ✅Simplified Integration: Agents interact with MCP tools via well-defined API contracts. The complexity of external API calls is encapsulated within the tool's implementation, not in the agent's core logic.

Defining an MCP Tool with `FastMCP`

The `@mcp.tools()` decorator from `FastMCP` turns a standard Python asynchronous function into a fully-fledged, documented, and standardized MCP-compliant API endpoint. It leverages Pydantic models for automatic request validation, type hinting for clear arguments, and docstrings for rich descriptions, all of which are used to generate the underlying MCP schema.

from mcp.server.fastmcp import FastMCP
from pydantic import BaseModel, Field
from typing import Optional

# Initialize FastMCP application. This acts as the FastAPI application instance.
mcp = FastMCP(
    title="My Agentic Tools",
    description="A collection of MCP-compliant tools for agentic applications.",
    version="1.0.0"
)

# Define Pydantic models for input and output data.
# These models automatically generate the JSON Schema for the MCP definition.
class WeatherInput(BaseModel):
    city: str = Field(..., description="The name of the city for which to get weather.")
    country_code: str = Field(..., description="The 2-letter ISO country code (e.g., US, UK, FR).")

class WeatherOutput(BaseModel):
    city: str
    country_code: str
    temperature: float = Field(..., description="Temperature in Celsius.")
    conditions: str = Field(..., description="e.g., 'Clear Sky', 'Partly Cloudy'.")
    humidity: Optional[int] = Field(None, description="Humidity percentage.")

# Use the @mcp.tools() decorator to define an MCP tool.
# FastMCP inspects the function signature, Pydantic models, and docstrings
# to automatically generate the MCP definition and expose it as an API endpoint.
@mcp.tools(
    tool_id="get_current_weather", # Unique ID for the tool
    description="Retrieves the current weather conditions for a specified geographic location.",
    response_model=WeatherOutput # Specifies the Pydantic model for the tool's output
)
async def get_current_weather_mcp(input: WeatherInput) -> WeatherOutput:
    """
    Fetches the current weather for a given city and country code.
    This function simulates an external weather API call.
    
    Args:
        input: A WeatherInput object containing city and country_code.
    
    Returns:
        A WeatherOutput object with temperature, conditions, etc.
    """
    print(f"MCP Tool: Fetching weather for {input.city}, {input.country_code}...")
    # In a real scenario, this would make an actual HTTP request to a weather API.
    if input.city.lower() == "london" and input.country_code.upper() == "UK":
        return WeatherOutput(
            city=input.city,
            country_code=input.country_code,
            temperature=15.0,
            conditions="Cloudy",
            humidity=80
        )
    elif input.city.lower() == "new york" and input.country_code.upper() == "US":
        return WeatherOutput(
            city=input.city,
            country_code=input.country_code,
            temperature=25.5,
            conditions="Sunny",
            humidity=50
        )
    else:
        # Handle cases where data is not available or an error occurs.
        # In a production system, you might raise an HTTPException or return a specific error structure.
        print(f"Weather data not available for {input.city}, {input.country_code}.")
        return WeatherOutput(
            city=input.city,
            country_code=input.country_code,
            temperature=0.0, # Indicate no data
            conditions="Data Not Available",
            humidity=0
        )

Advanced: Agent-to-Agent (A2A) Communication

A significant challenge in complex agentic systems arises when different specialized agents need to collaborate. Without a standardized communication method, this can lead to a tangled web of custom integrations. The LangGraph A2A (Agent-to-Agent) implementation, built upon MCP, provides a robust solution.

The Problem: Non-Standardized Agent Communication

Consider a scenario with a "Customer Service Agent" and a "Technical Support Agent." If the Customer Service Agent encounters a technical query, how does it hand off to or consult with the Technical Support Agent?

  • ❌Lack of Interoperability: Without a common protocol, Agent A doesn't know how to "talk" to Agent B. They might use different internal data structures, communication channels (e.g., direct function calls vs. message queues), or expect incompatible input/output formats. This prevents seamless collaboration.
  • ❌Hardcoding & Tight Coupling: You would be forced to hardcode specific integration logic for every pair of agents that need to communicate. This creates a brittle system where adding a new agent or modifying an existing one requires updating many other parts of the codebase.
  • ❌Deployment & Scalability Challenges: If Agent B is a separate service, Agent A needs to know its specific API endpoint, authentication mechanisms, and request/response schemas. This reintroduces the same complexities that our Tachyon-Langchain Client solved for LLM interaction, but now for inter-agent communication.

The Solution: LangGraph A2A (Agent-to-Agent) via MCP Tools

The core idea behind LangGraph A2A is to treat other agents as **specialized MCP tools**. This means that any agent whose capabilities need to be exposed for inter-agent communication will define those capabilities using MCP and then be hosted as a standard API endpoint (e.g., using `FastMCP`).

A2A Communication Flow

🗣️

Agent A
(Customer Service)

Identifies need for tech support.

→ MCP Tool Call (`call_mcp_tool`)
🛠️

MCP Endpoint
(FastAPI Server)

Routes the request to Agent B.

→
⚙️

Agent B
(Tech Support)

Processes the request as a tool input.

By treating Agent B as a standardized MCP tool, Agent A doesn't need to know its internal logic. It just makes a predictable API call to Agent B's `FastMCP`-exposed endpoint, enabling a decoupled and scalable multi-agent system. Agent B then performs its specialized task and returns a structured MCP response.

Conceptual Example: Technical Support Agent as an MCP Tool

Here's how a "Technical Support Agent" could be defined as an MCP tool using `FastMCP` and then invoked by another agent.

1. Define Agent B's Capability as an MCP Tool (`tech_support_agent_mcp.py`)

This code defines the `diagnose_issue` capability of the Technical Support Agent as an MCP tool using `@mcp.tools()`. This will automatically generate its MCP definition and expose it via a FastAPI endpoint.

from mcp.server.fastmcp import FastMCP
from pydantic import BaseModel, Field
from typing import List, Optional

mcp_tech_support = FastMCP(
    title="Technical Support Agent Capabilities",
    description="MCP tools for technical issue diagnosis and resolution.",
    version="1.0.0"
)

class DiagnoseIssueInput(BaseModel):
    issue_description: str = Field(..., description="A detailed description of the technical problem.")
    user_id: str = Field(..., description="The ID of the user experiencing the issue.")

class DiagnoseIssueOutput(BaseModel):
    diagnosis: str = Field(..., description="The agent's diagnosis of the issue.")
    solution_steps: List[str] = Field(..., description="Recommended steps to resolve the issue.")
    escalation_needed: bool = Field(False, description="True if further escalation is required.")

@mcp_tech_support.tools(
    tool_id="diagnose_technical_issue",
    description="Diagnoses a technical problem and provides solution steps.",
    response_model=DiagnoseIssueOutput
)
async def diagnose_technical_issue(input: DiagnoseIssueInput) -> DiagnoseIssueOutput:
    """
    Simulates the Technical Support Agent diagnosing an issue.
    In a real scenario, this would involve an LLM and potentially other tools
    within Agent B's own LangGraph workflow.
    """
    print(f"Tech Support Agent diagnosing for user {input.user_id}: {input.issue_description}")
    
    diagnosis = f"Initial diagnosis for '{input.issue_description}'."
    solution_steps = []
    escalation_needed = False

    if "network" in input.issue_description.lower():
        diagnosis += " Appears to be a network connectivity issue."
        solution_steps = [
            "1. Check your internet connection.",
            "2. Restart your router.",
            "3. Try connecting to a different Wi-Fi network."
        ]
    elif "software" in input.issue_description.lower():
        diagnosis += " Likely a software configuration problem."
        solution_steps = [
            "1. Reinstall the problematic software.",
            "2. Check for driver updates.",
            "3. Clear application cache."
        ]
    else:
        diagnosis += " Further investigation required."
        solution_steps = ["1. Please provide more details about the issue to Agent B."]
        escalation_needed = True

    return DiagnoseIssueOutput(
        diagnosis=diagnosis,
        solution_steps=solution_steps,
        escalation_needed=escalation_needed
    )

2. Agent A Invokes Agent B as an MCP Tool

The "Customer Service Agent" (Agent A) can now invoke the `diagnose_technical_issue` MCP tool (which is actually Agent B) just like any other tool. The `call_mcp_tool` wrapper handles the underlying HTTP communication.

from langgraph.graph import StateGraph, END
from langchain_core.messages import HumanMessage, AIMessage, ToolMessage
from langchain_core.tools import tool
from typing import TypedDict, Annotated, List, Union
import operator
import requests
import json

# Define the state for Agent A's LangGraph workflow
class AgentAState(TypedDict):
    messages: Annotated[List[Union[HumanMessage, AIMessage, ToolMessage]], operator.add]

# This function simulates the actual HTTP call to the FastMCP endpoint of Agent B.
# In a real system, this would be a generic client that loads MCP definitions
# and makes HTTP requests.
def invoke_external_mcp_tool(tool_id: str, args: dict) -> dict:
    # This URL would point to the running FastMCP service of Agent B (e.g., http://localhost:8001)
    api_url = f"http://localhost:8001/tools/{tool_id}" 
    print(f"\nAgent A calling external MCP Tool (Agent B): {api_url} with args: {args}")
    try:
        response = requests.post(api_url, json=args) # Assuming POST for agent capabilities
        response.raise_for_status()
        return response.json()
    except Exception as e:
        return {"error": f"Failed to call external MCP tool {tool_id}: {e}"}

# LangChain Tool wrapper that Agent A's LLM will see and call.
# This tool internally calls our `invoke_external_mcp_tool` function.
@tool
def call_agent_b(issue_description: str, user_id: str) -> str:
    """
    Calls the Technical Support Agent (Agent B) to diagnose a technical issue.
    Args:
        issue_description: A detailed description of the technical problem.
        user_id: The ID of the user experiencing the issue.
    """
    result = invoke_external_mcp_tool(
        tool_id="diagnose_technical_issue",
        args={"issue_description": issue_description, "user_id": user_id}
    )
    return json.dumps(result) # Return as string for LLM to parse

# List of tools available to Agent A (including Agent B as a tool)
agent_a_tools = [call_agent_b]

# Mock LLM for Agent A (similar to previous section, but now knows about call_agent_b)
class MockAgentALLM:
    def invoke(self, messages):
        last_message = messages[-1]
        if isinstance(last_message, HumanMessage):
            content = last_message.content.lower()
            if "technical problem" in content or "internet not working" in content:
                # Agent A's LLM decides to call Agent B (the diagnose_technical_issue tool)
                return AIMessage(
                    content="",
                    tool_calls=[
                        {
                            "name": "call_agent_b",
                            "args": {
                                "issue_description": last_message.content,
                                "user_id": "test_user_456"
                            },
                            "id": "tool_call_id_a2a_1"
                        }
                    ]
                )
            else:
                return AIMessage(content=f"Hello from Agent A! You said: '{last_message.content}'. How can I assist you further?")
        elif isinstance(last_message, ToolMessage):
            # Agent A's LLM processes the output from Agent B
            tool_output = json.loads(last_message.content)
            if "diagnosis" in tool_output:
                response_text = f"Agent B's diagnosis: {tool_output['diagnosis']}\n"
                response_text += "Solution Steps:\n" + "\n".join(tool_output['solution_steps'])
                if tool_output['escalation_needed']:
                    response_text += "\nFurther escalation to a human expert is recommended."
                return AIMessage(content=response_text)
            else:
                return AIMessage(content=f"Agent B returned: {tool_output}")
        return AIMessage(content="Agent A is not sure how to respond.")

agent_a_llm = MockAgentALLM()

# Agent A node for LangGraph (similar to previous Agent class)
class AgentA:
    def __init__(self, llm_model, tools_list):
        self.llm = llm_model
        self.tools = {t.name: t for t in tools_list}

    def __call__(self, state: AgentAState):
        messages = state["messages"]
        last_message = messages[-1]

        if isinstance(last_message, ToolMessage):
            response = self.llm.invoke(messages)
            return {"messages": [response]}

        response = self.llm.invoke(messages)
        if response.tool_calls:
            print(f"\nAgent A decided to call tool (Agent B): {response.tool_calls[0].name} with args: {response.tool_calls[0].args}")
            tool_output = self.tools[response.tool_calls[0].name].invoke(response.tool_calls[0].args)
            return {"messages": [response, ToolMessage(tool_output, tool_call_id=response.tool_calls[0].id)]}
        else:
            return {"messages": [response]}

agent_a_node = AgentA(agent_a_llm, agent_a_tools)

# Define LangGraph workflow for Agent A
workflow_a = StateGraph(AgentAState)
workflow_a.add_node("agent_a", agent_a_node)
workflow_a.set_entry_point("agent_a")

def should_continue_a(state: AgentAState):
    messages = state["messages"]
    last_message = messages[-1]
    if isinstance(last_message, AIMessage) and last_message.tool_calls:
        return "agent_a"
    else:
        return END

workflow_a.add_conditional_edges(
    "agent_a",
    should_continue_a,
    {
        "agent_a": "agent_a",
        END: END
    }
)
app_a = workflow_a.compile()

# Example Usage of Agent A calling Agent B (simulated)
if __name__ == "__main__":
    print("\n--- Agent A (Customer Service) calling Agent B (Tech Support) ---")
    user_query_a2a = "I have a technical problem: My home internet is not working."
    inputs_a2a = {"messages": [HumanMessage(content=user_query_a2a)]}
    for s in app_a.stream(inputs_a2a):
        print(s)
    print("\nFinal Agent A Response after consulting Agent B:", s[END]['messages'][-1].content)
